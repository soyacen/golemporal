# AGENTS.md - golemporal

This file provides guidance for AI coding agents working with the golemporal project.

## Project Overview

golemporal is a Temporal SDK framework for Go that uses protobuf-based code generation to define workflows and activities. It provides a protoc plugin (`protoc-gen-golemporal`) that generates type-safe Temporal workflow clients, activity clients, and worker registration code from proto service definitions.

### Key Features

- **Proto-based workflow definition**: Define workflows and activities in proto files
- **Type-safe code generation**: Generated code provides compile-time type checking
- **Functional options**: Workflow start options via functional configuration
- **Automatic registration**: Generated worker registration functions

## Technology Stack

- **Language**: Go 1.25+
- **Core Dependencies**:
  - `go.temporal.io/sdk` - Temporal Go SDK
  - `go.temporal.io/api` - Temporal API definitions
  - `google.golang.org/protobuf` - Protocol Buffers
- **Build Tools**: protoc (Protocol Buffers compiler)

## Code Generation Workflow

The project uses a proto-first approach:

1. **Define services in `.proto` files**:
   - Services ending with `Workflow` are treated as workflow services
   - Services ending with `Activity` are treated as activity services

2. **Generate code**:
   ```bash
   protoc \
     --proto_path=. \
     --go_out=. \
     --go_opt=paths=source_relative \
     --golemporal_out=. \
     --golemporal_opt=paths=source_relative \
     *.proto
   ```

3. **Generated code structure** (in `*_temporal.pb.go`):
   - Activity Client - Interface for invoking activities from workflows
   - Activity Server - Interface that activity implementations must satisfy
   - Workflow Client - Interface for starting workflow executions
   - Workflow Server - Interface that workflow implementations must satisfy
   - Register Function - Function to register workflow/activity with a Temporal worker

## Code Style Guidelines

### Naming Conventions

- **Workflow Services**: Must end with `Workflow` (e.g., `GreeterWorkflow`)
- **Activity Services**: Must end with `Activity` (e.g., `AddActivity`)
- **Generated Files**: `*_temporal.pb.go` (suffixed with `_temporal.pb.go`)
- **Interfaces**: Use descriptive names like `GreeterWorkflowClient`, `AddActivityServer`

### Import Organization

Standard Go import organization:
1. Standard library imports
2. Third-party imports
3. Internal/project imports

### Code Patterns

**Workflow Implementation**:
```go
type GreeterWorkflowServer struct {
    activity GreeterActivityClient
}

func (s *GreeterWorkflowServer) Hello(ctx workflow.Context, input *api.HelloRequest) (*api.HelloResponse, error) {
    ao := workflow.ActivityOptions{StartToCloseTimeout: 10 * time.Second}
    ctx = workflow.WithActivityOptions(ctx, ao)
    
    result, err := s.activity.Greet(ctx, &api.GreetRequest{Name: input.Name})
    if err != nil {
        return nil, err
    }
    return &api.HelloResponse{Message: result.Message}, nil
}
```

**Activity Implementation**:
```go
type GreeterActivityServer struct{}

func (s *GreeterActivityServer) Greet(ctx context.Context, input *api.GreetRequest) (*api.GreetResponse, error) {
    return &api.GreetResponse{Message: "Hello, " + input.Name + "!"}, nil
}
```

**Worker Registration**:
```go
api.RegisterGreeterWorkflowWorker(w,
    &GreeterWorkflowServer{activity: api.NewGreeterActivityClient()},
    &GreeterActivityServer{},
)
```

**Workflow Client Usage**:
```go
gc := api.NewGreeterWorkflowClient(c, "my-task-queue")
var result api.HelloResponse
err := gc.Hello(ctx, &api.HelloRequest{Name: "World"}, starter.GetResult(&result))
```

## Testing Instructions

Currently, the project does not contain automated tests. Testing is done manually using the example:

1. **Start a Temporal server** (requires Temporal running on `localhost:7233`):
   ```bash
   # Using Temporal CLI or Docker
   temporal server start-dev
   ```

2. **Start the worker**:
   ```bash
   cd example/worker && go run main.go
   ```

3. **Start the workflow** (in another terminal):
   ```bash
   cd example/starter && go run main.go
   ```

## Security Considerations

### Generated Code Security

- The generated code registers workflows and activities with `DisableAlreadyRegisteredCheck: true`
- Be cautious when using multiple workers or reloading workers in the same process

### Dependencies

- The project depends on Temporal SDK which handles security aspects like:
  - mTLS authentication support
  - API key authentication support
  - Data encryption in transit
- See `skills/temporal-go-sdk/` for security best practices with Temporal

### Secrets Management

- Never commit secrets or credentials to the repository
- Use environment variables or secure secret management for Temporal connection credentials
- The `.gitignore` already excludes `.env` files

## Development Notes

### Version Management

The version is hardcoded in `cmd/protoc-gen-golemporal/main.go`:
```go
var Version = "v0.0.2"
```

Use the GitHub Actions release workflow to update the version properly.

### Adding New Workflow Options

To add new workflow start options:
1. Add the option function in `starter/option.go`
2. Follow the existing pattern of functional options
3. Update the `Options` struct if needed

### Modifying Code Generation

When modifying the protoc plugin (`cmd/protoc-gen-golemporal/main.go`):
1. Test the changes by regenerating the example code
2. Ensure the example still compiles and runs
3. Update version if making significant changes
